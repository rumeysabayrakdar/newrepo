Arçelik App Store — General Design

Version 3.4 · 18 November 2026 · approved HTML review 32

Scope and architecture

One .NET 10 / React / PostgreSQL application serves the catalogue. Node.js compiles the React shell; it is not the API server. AppStore:Environment in appsettings.json selects Test or Production. One process uses one mode; switching requires restart/deploy. Separate databases can use the same PostgreSQL service, but Test and Production must not share the same catalogue database.

Navigation and employee experience

The home page has two primary destination cards. Applications scrolls smoothly to the catalogue; Web & portals opens its own view with a return link. The repeated header tabs are removed. Reduced-motion preferences are respected. Application cards contain logo, name and labels, in an equal-height grid. The same card remains alongside the detail. A second favourite button is not repeated in the detail. Descriptions have one 150-character editing field. Details keep platform/version/download choices compact; comments and resources remain available without repeating the description.

The available catalogue views are Cards and Compare. List view is removed and old saved List preferences become Cards. Compare lets the employee choose two applications and compare their relevant platform/download information. Filters support multiple categories, platforms and labels; OR within a group and AND between groups. Filters start closed. New arrivals is a compact strip linking to the corresponding details. Both light and dark themes are supported.

Applications have a unified catalogue, with no developed-in-house / other split. Web & portals retains Company-developed / External sites, with standard compact company-tool cards and topic-grouped external resources. Topics remain visible; expansion occurs inside a topic. Company portals retain background-image cards. Connecta, Atlas and Mate can be edited by the administrator. Some initial external addresses still point to BeHome and need administrator replacement with their actual destinations. Web tools cannot receive comments.

Favourites use yellow outline/filled stars and a compact expandable side stack. A red remove X sits beside the logo. Pencil and close controls have no circular containers. The profile initials are the deliberate exception: a red circular avatar.

Mobile

Below 900 px the header contains only the hamburger control. Branding, profile, theme, language and feedback move into its menu. Mobile shows no administration panel, role-preview controls or edit pencils, even for an administrator. Employees still use filters, favourites, details, downloads and feedback. Administrative work remains on desktop. This is a presentation restriction; server role checks still control all mutations regardless of screen width.

Administration

Six desktop navigation groups collect overview, catalogue, discovery, appearance, feedback and access functions. The app editor uses three compact sections: basic information with closed category/platform/label multi-selects and publishing options; downloads with images/documents; audience. Platform and version live on the download link. Redundant root-version, symbol, accent-colour, link-label and release-difference questions are removed while their existing stored values are preserved. Description textareas grow to show their content. File selection supports multiple images/documents and choosing a card image. APK upload remains a separate download delivery option.

Outside clicks and close controls dismiss panels. Unsaved edits require a discard decision; saving/uploading blocks accidental closing. Changes are not represented as saved until the API commits them.

Audience and identity

An administrator chooses everyone, company codes, country codes or mail groups, using comma-separated values. Targeting metadata is stored in PostgreSQL. Norm maps verified Okta values into the configured forwarded headers; the server filters employee bootstrap data and rechecks access to downloads, files and comments. Matching is case-insensitive. Multiple values within a field are OR; if legacy data specifies several fields, the groups combine with AND. A selected audience without values matches nobody. Missing identity claims do not grant a match. Existing site targeting remains until explicitly replaced through the audience editor.

The requested trusted-gateway CIDR check is removed from both startup and request handling. This application uses Norm's authentication gateway, not a standalone Okta OAuth client. Norm must authenticate the user, overwrite inbound identity headers and block direct access that bypasses the gateway. Required identity headers remain validated; uploading this ZIP alone does not configure Norm/Okta.

Data and operations

Shared catalogue, favourites, comments, feedback and file bytes are stored in PostgreSQL. Feedback is submitted with Send and appears in Administration > Feedback. No email or external ticket dispatch is configured. Documents/images accept up to 10 MB per file; APK accepts up to 100 MB and must contain AndroidManifest.xml. Downloads are browser attachments, not automatic installation. Unpublished uploads may remain after cancelling; retention/cleanup is an operations follow-up.

Existing catalogue and audit records are preserved by additive schema changes. Startup initializes tables and seeds only a previously uninitialized experience store. No live database dump, password, Okta secret or real APK is included. Dashboard numbers remain labelled sample metrics, not confirmed installations.

Validation and handoff

Checked locally: Node build, .NET build; React + .NET + PostgreSQL save/favourite/comment/feedback; employee write denial; gateway headers without CIDR; missing/invalid identity rejection; PostgreSQL document upload/download; company/group eligibility and denied access; APK upload/download. Norm deployment, real Okta claim names and live network rules require validation on the hosting platform. This document replaces earlier design versions.
