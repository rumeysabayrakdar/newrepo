Arçelik App Store — General Design

Version 3.0 · 16 November 2026 · TEST candidate

Scope and architecture

The approved responsive store is delivered inside the existing .NET 10 / React / PostgreSQL application. Node.js is used for React compilation, not as a replacement API server. PostgreSQL is mandatory. Existing catalogue records and the original tables are preserved by an additive migration.

Employee experience

Applications retain Developed / Other tabs, multi-select category/platform/label filters, search, Cards / List / Compare views, app details, platform download links, documents and screenshots. Filter groups use OR within each group and AND between groups. Filters start closed. Featured applications use compact glass cards with visible light/dark decoration rings and open the corresponding app details. User comments show text on the card; author and time remain in the detail screen. Web-only tools cannot receive comments.

Web & portals has Developed in-house / External sites views, defaulting to in-house. Connecta, Atlas, Mate and a targeted Sütlüce cafeteria link are TEST starter listings. Internal cards have administrator-selected sizes/order and an animated burgundy perimeter, including corners. External sites retain the compact topic overview; every topic is visible and has its own expansion control. Company portal photo cards remain in the internal view. Per-resource addresses are independently editable; a number of starter external resources still route through BeHome until real links are supplied.

Favourites and likes are separate per-employee preferences stored in PostgreSQL. The compact corner stack opens vertically. Removing an item from visible eligibility does not delete its saved preference. Display theme/language preferences and unsent feedback drafts may remain browser-local; catalogue data never falls back to browser storage.

Administrator experience

The top Administration button is the main management entry. Admins can update current-language text, shared images/URLs/categories, activity/audit views, featured selections, filters, catalogue order/column count and internal card sizes. Shared saves require the existing confirmation, commit immediately and use optimistic concurrency. Unsaved edits are private. Backdrop dismissal respects unsaved changes. Admin assignment is to registered employees; unknown sicil labels do not create employees or silently grant access. No Super Admin or approval workflow is introduced.

TEST personas and identity

Configured TEST users can be selected in the TEST account menu. Administrators can create explicitly synthetic TEST profiles with test employee label, company, country and office. Only an already authorized TEST administrator can select these via the API; an employee simulation cannot execute admin writes. No real employee lookup is performed. These facilities are rejected outside TEST. Actual Production identity still uses the trusted Okta gateway integration; real claim mapping and infrastructure are not completed by this release. Company code is not treated as equivalent to a physical building. Sütlüce visibility uses the explicit sample office rule.

Feedback and reporting

Help, suggestion, complaint and application idea/need submissions are received in PostgreSQL. Administrators can read the messages under Activity. No email, external support ticket or automatic notification is sent. Dashboard download/visit/trend numbers are clearly marked SAMPLE DATA. The readiness ring is computed from active links in the current catalogue. An open/download request does not prove installation.

Environments, delivery and limits

This archive is TEST only. It includes source, compiled static assets, SQL schema, seed files, Docker/Compose configuration and these documents. It does not contain a live database dump or credentials. Schema setup and one-time legacy catalogue migration run at startup. Existing experience state is never reset to starter data. TEST and PROD must use separate databases. Platform ingress/TLS issues cannot be fixed by the ZIP. Browser-local edits made in the older standalone HTML preview are not automatically imported into PostgreSQL.

Acceptance for this candidate

React and .NET builds; PostgreSQL-backed admin save; employee write rejection; persisted favourites; shared comments; basic redirect/feedback/concurrency/persona checks. This is a bounded TEST candidate, not a production sign-off or exhaustive browser/security test. Pending: corporate Okta field mapping, final portal/tool URLs and brand assets, live analytics, notification workflow, infrastructure validation and release acceptance.
